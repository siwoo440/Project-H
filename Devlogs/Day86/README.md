# Part 1. 스탠딩 다시 그리기

76일차에 넣은 스탠딩은 8등신에 묘사가 촘촘한 그림이었다. 이 그림이 마음에 들지 않아 방향을 바꿨다.

| | 76일차 그림 | 86일차 그림 |
| --- | --- | --- |
| 비율 | 8등신 | 4.5등신 안팎 |
| 채색 | 묘사가 촘촘함 | 단순한 셀 채색 |
| 인상 | 사실적 | 귀엽고 데포르메 |

## 견본을 먼저 받았다

88장을 한 번에 받으면 방향이 틀렸을 때 전부 다시 그려야 한다. 그래서 **세레나의 표정 7장만 먼저** 받아 그림체를 확인하고, 그다음 전체를 받았다.

## 받은 그림 확인

| 확인한 것 | 결과 |
| --- | --- |
| 크기 | 88장 모두 1024×1536 |
| 머리 · 발 위치 | 머리 꼭대기 25~26, 발끝 1509~1510으로 12명이 같다 |
| 표정 차이 | 표정을 바꿔도 얼굴 상자 밖은 한 픽셀도 달라지지 않는다 |
| 파일 이름 | 기존과 같다 — 그대로 덮어쓰면 된다 |

파일 이름이 같으므로 **그림을 불러오는 코드는 고칠 것이 없다.** 고칠 것은 "얼굴이 어디 있는가"와 "얼마나 크게 보여 줄 것인가" 두 가지다.

## 얼굴 위치표를 다시 쟀다

초상화와 궁극기 컷인은 스탠딩에서 얼굴을 잘라 쓴다. 머리가 커졌으니 얼굴 위치도 달라진다.

| | 76일차 그림 | 86일차 그림 |
| --- | --- | --- |
| 얼굴 중심 높이 | 위에서 약 178 | 위에서 약 257 |
| 얼굴 높이의 절반 | 캐릭터마다 58~62 | **12명 공통 88** |
| 초상화로 자르는 한 변 | 약 317 | 약 458 |

- 가로 · 세로 중심은 **표정이 바뀌는 영역의 가운데**를 재서 넣었다
- 얼굴 높이는 12명에게 같은 값을 쓴다. 머리 크기를 같게 그린 그림이라, 캐릭터마다 다른 값을 쓰면 초상화에서 머리 크기가 들쭉날쭉해진다

## 대화 화면 배율 : 1.4 → 1.25

대화 화면은 스탠딩을 확대해 아래쪽을 잘라 보여 준다. 예전 배율 1.4를 그대로 쓰면 머리가 큰 새 그림은 화면을 너무 많이 차지한다.

화면을 직접 볼 수 없으므로 **실제 그림과 실제 대화창 그림을 합성**해 1.25와 1.4를 나란히 놓고 비교했다. 1.25는 무릎까지 보이고 두 사람이 설 때 서로 가리지 않는다.

## 바꾸지 않은 것

| 대상 | 이유 |
| --- | --- |
| 전투 SD 그림 46장 | 원래 2등신이라 새 그림체와 어긋나지 않는다 |
| 궁극기 컷인 · 이벤트 CG 요청 | 예전 그림체로 써 둔 요청문이다. 새 그림체로 다시 써야 한다 |

# Part 2. 전투 화면 마무리

85일차까지 창과 버튼은 모두 새 그림이 되었지만 **게이지는 색 상자 그대로**였다.

| 대상 | 바뀐 점 |
| --- | --- |
| 하단 카드의 체력 · 궁극기 | 어두운 홈 + 광택 있는 채움 |
| 유닛 머리 위 체력바 | 같은 그림. 작은 막대라 모서리를 작게 |
| 보스 체력바 | 남색 판 위에 게이지. 페이즈 눈금은 그대로 |
| 흐트러짐 게이지 | 같은 그림. 상태별 색 변화는 그대로 |
| 스킬 블록 판 | 판은 어두운 창, 블록이 놓이는 7칸은 은테 칸 |
| 상점 · 대장간 골드 | `● 5,548 G` → 숫자 오른쪽에 금화 아이콘 |
| 전투 결과창 | `BATTLE RESULT` → `전투 결과` |

## 게이지 색은 그대로 나온다

게이지 채움 그림은 **흰색**으로 받았다. 흰 그림에 색을 곱하면 그 색이 그대로 나온다. 그래서 체력의 초록, 궁극기의 금색, 흐트러짐의 상태별 색을 정하는 코드는 하나도 고치지 않았다.

바탕은 반대다. 예전 바탕은 어두운 상자 색이었는데 이 색을 그림에 곱하면 홈이 새까맣게 죽는다. 바탕은 흰색으로 돌려 그림 색을 그대로 쓴다.

```csharp
UiSkinKit.Gauge(hpFillImage); // 채움과 그 부모(바탕)에 함께 입힌다
```

## 게이지가 줄어도 모양이 깨지지 않는다

이 게임의 게이지는 전부 **채움의 폭을 줄이는 방식**이다. 9조각 그림은 폭이 달라져도 모서리가 늘어나지 않으므로 체력이 줄어도 둥근 끝이 유지된다. 전투 계산에는 손대지 않았다.

## 입히지 않은 것

| 대상 | 이유 |
| --- | --- |
| 스킬 블록 | 블록의 색이 강화 단계(1~3)를 나타낸다 (임시 색) |
| 리듬 판정 화면 | 판정선과 노트의 색이 놀이의 정보다 |

# Part 3. Test Runner 실패 2건

Unity의 Test Runner를 돌린 결과 2건이 실패했다.

## 1. 지도 안내 아이콘이 바뀌어 있었다

| | 내용 |
| --- | --- |
| 실패 | `GuideIcon_IsDrawnShape` — `Texture 'alert' is not readable` |
| 원인 | 82일차에 넣은 메뉴 아이콘 `UI/Icons/alert.png`가 66일차의 지도 안내 아이콘이 찾는 자리 `UI/Icons/ALERT`와 겹쳤다 |
| 실제 영향 | 모험 지도에서 새 던전을 알리는 **노란 안내 아이콘 대신 흰 느낌표**가 나오고 있었다 |
| 수정 | 지도 위 아이콘의 자리를 `Map/ALERT` · `Map/RIFT`로 옮겼다 |

`Resources` 경로는 **대소문자를 가리지 않는다.** 코드에는 "정식 그림을 넣으면 그 그림을 쓴다"는 자리가 여러 곳에 있고, 새 그림의 이름이 그 자리와 우연히 겹치면 엉뚱한 그림이 불려 온다. 82일차부터 86일차까지 이 상태였다.

## 2. 초상화 크기 범위가 옛 그림 기준이었다

| | 내용 |
| --- | --- |
| 실패 | `PortraitRect_IsSquareInsideSpriteAndContainsFace` — 250~400이어야 하는데 457 |
| 원인 | 머리가 큰 새 그림은 초상화로 자르는 영역도 크다. 테스트의 범위가 8등신 기준이었다 |
| 실제 영향 | 없음 (화면은 정상) |
| 수정 | 범위를 250~520으로 넓혔다 |

## 알아둘 점

- **새 그림의 이름이 기존 코드가 찾는 경로와 겹치지 않는지 확인할 것.** `Resources` 경로는 대소문자를 가리지 않는다

- 게이지는 `UiSkinKit.Gauge`로 입힌다. 채움 색은 코드가 넣는 색이 그대로 보인다
- 스탠딩을 다시 받으면 `StandingFaceCatalog`를 다시 재고 `DialogueStandingFrame.Scale`을 확인한다
