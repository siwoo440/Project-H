# Part 1. 로비 — 시간대 배경과 대표 동료

## 시간대 배경

게임에는 아침 · 점심 · 저녁 · 밤이 흐른다. 그런데 로비는 언제 들어가도 같은 화면이었다. 대화 배경에 이미 시간대별 그림 4장이 있어서 그대로 연결했다.

| 시간대 | 배경 |
| --- | --- |
| 아침 | `MORNING` |
| 점심 | `DAY` |
| 저녁 | `EVENING` |
| 밤 | `NIGHT` |

- 로비에 머문 채 시간이 넘어가도 배경이 따라 바뀐다. 매 프레임 그림을 다시 넣는 것이 아니라 **시간대 값이 달라졌을 때만** 다시 그린다
- 배경 위에 옅은 어두운 막(16%)을 깐다. 로비는 패널마다 바탕이 있어서 전투(28%)보다 옅게 잡았다

## 대표 동료

씬에는 `MAIN CHARACTER`라고 적힌 임시 칸이 있었다. 그 자리에 **파티 첫 자리 동료의 스탠딩**을 세운다. 파티를 바꾸면 따라 바뀐다. 파티가 비어 있으면 첫 동료를 쓴다.

## 공용 기능 `SceneBackdrop`

"씬에 놓인 배경 이미지를 찾아 그림을 넣고, 비율을 맞추고, 어두운 막을 한 겹 깐다"는 78일차 전투 배경에서 이미 하던 일이다. 로비도 같은 일을 해야 해서 **공용 기능으로 꺼냈고**, 전투 배경은 그것을 부르도록 줄였다(30줄 감소).

# Part 2. 세계 지도

## 검사

| 항목 | 결과 |
| --- | --- |
| 크기 | 1400×1100 · 완전 불투명 · 글자와 표시 없음 |
| 지역 좌표 | 요청문에 넣은 9개 좌표가 지형과 일치 (설원 · 균열지대 · 늪 · 노아르 · 숲 · 실바란 · 마을 · 바다 · 사막) |

지도 영역은 기준 화면(1600×900)에서 1048×823.5, 가로 ÷ 세로가 1.2726이다. 그림은 1400×1100 = 1.2727이라 **16:9에서는 늘어나지 않고 딱 맞는다.**

## 비율 유지

지금까지 지도는 영역에 맞춰 **늘려서** 그렸다. 코드로 칠한 얼룩일 때는 티가 나지 않았지만, 그린 지도는 16:10 화면에서 세로로 11% 늘어난다.

| | 전 | 후 |
| --- | --- | --- |
| 지도 | 영역에 맞춰 늘림 | 비율을 지켜 영역 안에 맞춤 |
| 남는 자리 | 없음 | 지도 가장자리와 같은 바다색 |
| 지역 표시 | 화면 기준 좌표 | **지도 그림의 자식** (지도 기준 좌표) |

지역 표시를 지도 위에 직접 올린 것이 핵심이다. 지도가 어떤 크기로 놓이든 표시는 같은 땅 위에 있다.

"영역을 꽉 채우고 넘치는 부분을 자르는" 방식도 따져 봤다. 21:9 화면에서 위아래가 12%씩 잘려 설원과 사막의 지역 표시가 화면 밖으로 나간다. 그래서 다 보이는 쪽을 골랐다.

## 가져오기 설정

지도 PNG는 투명 채널이 있지만 전부 불투명하다. `.meta`에서 투명 채널을 쓰지 않도록 해 절반 크기로 압축되게 했다.

## 그림을 찾는 순서 `ItemIconArt`

1. `Resources/Icons/Items/{아이템ID}.png`
2. 아이템 데이터에 연결된 그림
3. 없으면 색 원과 글자 (예전 표시)

아이템을 새로 추가하고 그림이 아직 없어도 화면이 깨지지 않는다.

## 연결한 화면

| 화면 | 전 | 후 |
| --- | --- | --- |
| 가방 칸 | `[01]` 번호 · 이름 · 수량 글자 | 아이콘 + 이름 · 수량 |
| 가방 상세 | 데이터에 연결된 그림만 | 아이콘 파일 우선 |
| 캐릭터 화면 장비 5칸 | 부위 글자 | 장착한 장비의 아이콘 (빈 칸은 글자 그대로) |
| 선물하기 | 글자 버튼 | 버튼 왼쪽에 선물 그림 · 보유 0개면 흐리게 |
| 상점 · 대장간 | 색 원과 글자 | 61일차에 만든 아이콘 칸이 자동으로 그림 표시 |

캐릭터 화면의 **보유 장비 목록**은 그대로 두었다. 칸이 좁아 아이콘을 넣으면 옵션 글자가 줄바꿈되어 마지막 줄이 잘린다.

# Part 4. 그림 불러오기 최적화

## 문제 1 — 매번 한 번씩 실패하던 조회

`RuntimeSpriteLoader.Load`는 그림을 이렇게 찾았다.

1. Sprite 형식으로 찾는다
2. 없으면 캐시를 본다
3. 없으면 Texture 형식으로 찾아 Sprite로 바꾼다

그런데 이 프로젝트의 그림은 **전부 Texture 형식**이다. 그래서 1번은 항상 실패했고, 같은 그림을 다시 부를 때마다 실패하는 조회를 한 번씩 거친 뒤에야 캐시에 닿았다.

→ **캐시를 먼저** 본다.

## 문제 2 — 없는 그림을 계속 찾던 것

스탠딩은 `{ID}_{표정}` → `{ID}_normal` → `{ID}` 순으로 찾는다. 없는 경로는 부를 때마다 디스크를 다시 뒤졌다.

→ 없다고 확인한 경로를 기억한다. 단 **플레이 중에만** 기억한다. 에디터에서는 그림을 넣자마자 보여야 하기 때문이다.

## 문제 3 — 캐시가 그림을 붙잡고 있던 것

캐시에 든 그림은 화면에서 쓰지 않아도 메모리에서 내려가지 않는다. 대화를 몇 편 보면 배경과 스탠딩이 계속 쌓였다.

→ **씬이 내려갈 때 캐시를 비운다.** 그림을 지우는 것이 아니라 붙잡은 손만 놓는다. 화면에서 쓰고 있는 그림은 그대로 남고, 쓰지 않는 그림은 엔진이 정리한다.

## 문제 4 — 가려진 그림까지 불러오던 일기장

일기장 갤러리는 **잠긴 칸도** 배경과 컷인 그림을 불러온 뒤 가려 두었다. 칸을 열 때마다 큰 그림 수십 장이 한꺼번에 올라왔다.

→ 열린 칸 · 합류한 동료의 그림만 불러온다.

## 일기장 CG 목록 12인

CG 목록이 초기 4인(12칸)으로 남아 있었다. 개인 1화 · 결속 · 여관 대사는 70일차부터 12인 모두 있으므로 **36칸**으로 넓혔다. 79일차 일지에 "그림이 오면 할 일"로 적어 둔 것이다.

# Part 5. 배경이 압축되지 않고 있었다

## 발견

대화 배경은 1672×941이다. Unity의 그림 압축은 **4×4 칸 단위**로 한다. 941은 4의 배수가 아니다.

Unity가 그림을 가져와 저장해 둔 폴더(`Library/Artifacts`)를 파일 크기로 살폈다.

| 크기 | 뜻 | 개수 |
| --- | --- | --- |
| 4.72MB | 1672×941을 압축 없이 저장한 크기 | **37개** |
| 1.57MB | 스탠딩 같은 1024×1536 그림을 압축한 크기 | 91개 |

37개는 배경 36장 + 타이틀 배경 1장과 정확히 같다. **배경 전부가 원본 그대로 올라가고 있었다.**

## 수정

| 대상 | 전 | 후 |
| --- | --- | --- |
| 대화 · 화면 배경 36장, 타이틀 배경 1장 | 1672×941 | 1672×**940** |
| 지역 아이콘 8개 | 386×386 | **388**×388 |

배경은 **맨 아래 1줄만 떼어 냈다.** PNG는 한 줄씩 따로 저장하고 각 줄은 윗줄만 참조한다. 그래서 그림을 풀었다 다시 저장하지 않고 마지막 줄만 빼낼 수 있다. 남은 줄의 색은 한 값도 바뀌지 않는다. 자른 뒤 원본과 줄 단위로 같은지 검사했다.

예상 효과는 배경 한 장이 4.7MB에서 0.8MB로, 37장 기준 **약 175MB가 30MB**가 되는 것이다. 메모리와 빌드 용량 양쪽에 해당한다.

## 재발 방지

`Resources`의 모든 그림이 4의 배수 크기인지 검사하는 테스트를 추가했다. 941 같은 크기가 다시 들어오면 파일 이름과 함께 실패한다.

GPT가 만드는 배경은 계속 1672×941로 온다. **넣을 때 940으로 자른다.**

## 알아둘 점

- **그림의 가로 · 세로는 4의 배수여야 한다.** 아니면 압축되지 않아 메모리와 빌드 용량을 6배쯤 쓴다. 로컬 빌드로는 드러나지 않는다
- **지도 위에 놓는 것은 지도 그림의 자식으로 둘 것.** 화면 기준으로 놓으면 16:9가 아닌 화면에서 다른 땅 위에 놓인다
- **그림은 `RuntimeSpriteLoader.Load`로 불러올 것.** 따로 `static`에 붙잡아 두면 씬이 바뀌어도 메모리에서 내려가지 않는다
- **화면에 보이지 않는 그림은 불러오지 말 것**
- 아이템 그림은 `ItemIconArt.Get`, 등급 테두리가 있는 칸은 `ItemIconView`를 쓴다
- 로비 배경의 어둡기는 `LobbyBackdropCatalog.DimAlpha`로 조절한다
- 배경 37장이 바뀐 파일로 잡혀 이번 커밋으로 저장소가 약 110MB 커진다
