# Part 1. 저장 안전장치 — `SaveFileStore`

## 문제

저장은 기존 파일 위에 **바로 덮어쓰는** 방식이었다. 쓰는 도중에 게임이 꺼지면 파일이 반만 쓰인 채 남고, 백업이 없어 진행이 통째로 사라진다. 저장은 아이템 구매 · 장비 교체 등 35곳에서 수시로 일어난다.

지난 일지에 "자동 저장"을 다음 작업으로 적었는데, 확인해 보니 이미 행동마다 저장되고 있었다. 필요한 것은 저장을 **안전하게** 만드는 일이었다.

## 바꾼 것

| 항목 | 전 | 후 |
| --- | --- | --- |
| 쓰는 방식 | 기존 파일에 바로 덮어씀 | 임시 파일(`.tmp`)에 다 쓴 뒤 한 번에 교체 |
| 백업 | 없음 | 직전 저장 1개(`.bak`) |
| 읽기 실패 | "불러올 수 없습니다" | 백업으로 복구하고 로비에서 한 번 안내 |
| 삭제 | 원본만 삭제 | 백업 · 임시 파일까지 삭제 |

- **깨진 원본은 백업으로 넘기지 않는다.** 원본이 온전한지는 첫 글자 `{`와 끝 글자 `}`만 본다. 전체를 해석하지 않아 저장할 때마다 불러도 부담이 없다
- **지울 때 백업을 남기면 지운 저장이 되살아난다.** 그래서 삭제는 세 파일을 함께 지운다
- 저장을 부르는 35곳은 건드리지 않고 `SaveManager` 안에서만 바꿨다
- 이어하기 파일과 저장 칸 모두에 적용된다

## 확인

저장 로직은 Unity 없이도 돌릴 수 있어 실제 파일로 16가지 상황을 돌려 보았고 모두 통과했다. 다만 일반 .NET에서 돌린 것이라 Unity 안에서의 동작은 Test Runner로 확인해야 한다.

# Part 2. 이미 본 이야기 빨리 넘기기

| 기능 | 내용 |
| --- | --- |

| 안내 | 화면 구석에 "이미 본 이야기 · Ctrl 빨리 넘기기" |
| 설정 | "처음 보는 대사도 빨리 넘기기 (Ctrl)" — 기본 꺼짐 |

## 회차를 넘는 기록

"본 이야기" 기록은 저장 파일 안에 있어서 **새 게임을 시작하면 비워졌다.** 2회차에서 빨리 넘기기를 쓰려면 회차를 넘겨 남아야 한다. 그래서 끝까지 본 이야기를 회차 기록(`PlayerProfile`)에도 남긴다.

## 한계

기록은 **끝까지 본 대본 단위**다. 중간에 그만둔 이야기는 안 본 것으로 취급한다. 줄 단위 기록은 저장 파일이 커져서 넣지 않았다.

# Part 5. 그림 없이 고친 것

## 재화 표시

로비 상단의 골드는 실제 값을 보여 준다. 게임에 없는 크리스탈 칩은 숨겼다. 파티 화면의 골드도 실제 값이다.

## 초상화 자리 — `PortraitSlot`

이름 글자가 들어 있던 자리에 캐릭터 그림을 넣는 공용 기능이다. 그림이 없으면 글자를 그대로 둔다.

| 화면 | 그림 |
| --- | --- |
| 파티 슬롯 | 상반신 |
| 파티 캐릭터 선택 카드 | 얼굴 |
| 전투 결과창 | 상반신 (쓰러진 동료는 어둡게) |

상반신은 77일차의 얼굴 위치표를 그대로 쓴다. 머리 위 여백은 초상화와 같게 두고 아래로만 길게 자른다.

## 옛 화면 끄기

모험 지도 씬에는 지도 화면을 새로 만들기 전의 화면이 남아 있었다. 새 지도가 위를 덮어 보이지 않는데도 매 프레임 그려지고 있었다. 씬이 열릴 때 끈다. 씬 파일에서 지우지는 않았다.

## 영어 문구

| 전 | 후 |
| --- | --- |
| HP OK / LOW / DANGER / DOWN | 정상 / 주의 / 위험 / 쓰러짐 |
| ULT 50% / ULT READY | 궁극기 50% / 궁극기 준비 |
| TANK / HEALER / DEALER | 탱커 / 힐러 / 딜러 |
| WAVE 1 / 3 · AUTO ON · MENU | 웨이브 1 / 3 · 자동 켬 · 메뉴 |
| WIN! / LOSE · PARTY · ALIVE | 승리! / 패배 · 파티 · 생존 |
| NOW LOADING · SAVE FAILED · VIT | 불러오는 중 · 저장 실패 · 활력 |
| LOBBY · SET · LOG · EMPTY SLOT | 로비 · 설정 · 대화 기록 · 빈 자리 |

리듬 연출 글자(`FULL COMBO` · `TIMING!` · `MAX`)와 `PROJECT H` · `LV.`는 그대로 두었다. 씬 파일 3개(로비 · 파티 · 전투)에서는 글자 4줄만 직접 고쳤다.

# Part 6. UI 스킨 자리 — `UiSkin`

그림을 요청하기 전에 **코드가 읽을 이름 · 크기 · 테두리를 먼저 정했다.** 요청문은 이 표를 그대로 옮긴 것이다.

| 묶음 | 수 | 위치 |
| --- | --- | --- |
| 창 · 버튼 · 게이지 | 18 | `Resources/UI/Skin/{이름}.png` |
| 메뉴 · 내비 · 재화 아이콘 | 30 | `Resources/UI/Icons/{이름}.png` |
| 룬 | 15 | `Resources/Icons/Runes/{RuneKind}.png` |
| 상태이상 | 17 | `Resources/Icons/Status/{이름}.png` |
| 속성 | 5 | `Resources/Icons/Elements/{이름}.png` |

창과 버튼은 **9조각**으로 늘여 쓴다. 바깥 띠(모서리와 변)는 그대로 두고 가운데만 늘이는 방식이라, 그림마다 "늘어나지 않는 테두리 두께"가 규격에 들어 있다.

## 알아둘 점

- **저장 파일은 `SaveFileStore`로 쓰고 지울 것.** 바로 덮어쓰면 쓰는 도중 꺼졌을 때 진행이 사라지고, 지울 때 백업을 남기면 지운 저장이 되살아난다
- **글자의 폰트는 `RuntimeUiKit.DefaultFont`.** 기본 폰트를 직접 지정하면 정식 폰트를 넣어도 그 글자만 바뀌지 않는다
- **회차를 넘겨 "본 이야기"를 물을 때는 `DialogueSkipRules.IsSeen`.** 저장 파일의 기록은 새 게임에서 비워진다
- **초상화 자리에는 `PortraitSlot.Apply`**
- 한글은 영어보다 넓다. 전투 HUD의 좁은 칸(궁극기 게이지 · 웨이브 표시)에서 글자가 넘치는지 확인이 필요하다
- 폰트 제안 때 "폰트 자리가 없다"고 했던 것은 틀렸다. 73일차부터 있었고 빈틈만 있었다
