# Part 2. 버튼 소리

## 빈틈이 생긴 이유

버튼 소리는 `RuntimeUiKit.CreateButton` 한 곳에서 붙이고 있었다. 이 함수를 거치지 않는 버튼은 소리가 없었다.

| 버튼 | 붙이는 곳 |
| --- | --- |
| 코드로 만든 버튼 | `RuntimeUiKit.CreateButton` (기존) |
| 씬에 놓인 버튼 | `ButtonSoundScenePatch` — 씬이 열릴 때 소리 없는 버튼을 찾아 붙인다 (신규) |
| 직접 만든 버튼 7곳 | 만드는 자리에서 `UiSound.Attach` (신규) |

씬 파일은 건드리지 않았다. 82일차에 스킨을 씬 화면에 입힌 것과 같은 방식이다.

## 소리가 두 번 나지 않게

버튼에 소리를 붙일 때 `UiButtonSound`라는 표시를 함께 붙인다. 표시가 이미 있으면 다시 붙이지 않는다. 씬 버튼 연결과 코드 버튼 생성의 순서가 어떻게 되든 한 번만 난다.

## 버튼 이름으로 소리를 고른다

모든 버튼이 같은 "딸깍"이면 닫는 것과 여는 것이 구분되지 않는다. 버튼 오브젝트의 이름을 보고 소리를 고른다.

| 이름에 들어 있는 낱말 | 소리 |
| --- | --- |
| Close · Back · Cancel · No · 닫기 | 취소 |
| Confirm · Yes | 확인 |
| Tab · Filter · Next · Prev · Page · Nav | 넘김 |
| Catcher · Dim (화면 전체를 덮는 투명 버튼) | 무음 |
| 그 밖 | 딸깍 |

낱말 단위로 본다. `Background`의 Back, `Node_3`의 No, `Table`의 Tab은 해당하지 않는다.

이 방식 덕분에 화면 40여 곳의 버튼을 하나씩 고치지 않았다. 엉뚱한 소리가 나는 버튼은 `UiSound.Attach(버튼, 소리)`로 따로 지정할 수 있다.

## 대사 넘김 소리는 직접 넘길 때만

대사는 세 가지 경로로 넘어간다. 화면 클릭, 자동 진행, Ctrl 빨리 넘기기다. 소리는 **화면 클릭에만** 넣었다. 빨리 넘기기는 0.05초마다 넘어가서 소리를 넣으면 따발총처럼 들린다.

## 상점과 대장간은 NPC 대사가 곧 결과다

상점과 대장간은 결과에 따라 NPC가 다른 말을 한다. 그 "상황"이 이미 구매 성공 · 골드 부족 · 강화 실패처럼 나뉘어 있어서, 상황마다 소리를 정해 대사가 바뀌는 한 곳에 넣었다.

# Part 4. 배경음

## 새 곡 3개

| 곡 | 나는 때 |
| --- | --- |
| `BOSS` | 보스가 등장하는 순간 |
| `VICTORY` | 전투 승리 후 결과창 |
| `ENDING` | 엔딩 재생 |

패배하면 배경음을 끈다. 다음 화면으로 넘어가면 그 화면의 곡이 다시 나온다.

곡 파일이 없으면 원래 쓰던 곡이 대신 나온다 (보스전 → 전투, 승리 → 평상시, 엔딩 → 타이틀).

## 부드러운 전환

| 구간 | 시간 |
| --- | --- |
| 지금 곡이 줄어듦 | 0.35초 |
| 새 곡이 커짐 | 0.5초 |

- 같은 곡을 다시 요청하면 아무 일도 없다. 로비에서 상점으로 가도 곡이 처음부터 다시 시작하지 않는다
- 줄이는 도중에 원래 곡으로 돌아오면 바꾸지 않고 다시 키운다
- 전환은 실제 시간으로 진행한다. 전투가 멈춰 있어도(결과창) 곡이 바뀐다

# Part 5. 정리

## 같은 소리가 겹치지 않게

광역 공격이 네 명을 동시에 때리면 타격음이 네 번 겹쳐 시끄럽다. 같은 소리는 0.05초 안에 한 번만 난다. 타격은 0.08초로 조금 더 띄웠다.

## 소리별 크기

자주 나는 소리는 작게 했다.

| 소리 | 크기 |
| --- | --- |
| 타격 | 65% |
| 대사 넘김 | 50% |
| 버튼 · 넘김 | 80% |
| 그 밖 | 100% |

## 임시 음원

새 소리 17개(효과음 14 · 배경음 3)는 73일차와 같은 방식으로 코드로 합성했다. 규격은 기존과 같다 (22050Hz · 모노 · 16비트).

평균 크기를 기존 음원에 맞췄다. 처음에는 최고 음량 기준으로 만들었는데 "할 수 없음" 소리가 기존 버튼 소리의 두 배 크기로 나와서, 평균 크기 기준으로 바꿨다.

**소리를 직접 들어 보지는 못했다.** 음색이 어떤지는 Unity에서 확인해야 한다.

## 알아둘 점

- **버튼은 `RuntimeUiKit.CreateButton`으로 만들 것.** 직접 만들면 `UiSound.Attach`를 불러야 소리가 난다
- **소리를 추가하면 `AudioCatalog.AllSfx` · `AllBgm`에도 넣을 것.** 테스트가 이 목록으로 파일을 검사한다
- 결과가 정해지는 자리에서는 `UiSound.Result(성공 여부)`를 쓴다
- 정식 음원은 같은 이름의 `.wav`로 덮어쓰면 교체된다
