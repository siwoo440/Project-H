# 프로젝트 H : 49일차 개발 로그

## 오늘 목표

49일차의 목표는 **리듬 판정을 Perfect / Good / Miss 3단계로 확장하는 것**이었다. 여기에 더해, Day48에서 사각형으로만 그려져 있던 챌린지 UI를 실제 리듬게임처럼 다듬고 **박자(BPM) 개념을 설계해 넣는 작업**을 함께 진행했다.

핵심 흐름은 다음과 같다.

```text
궁극기 발동
↓
80 BPM 기준 한 박자(0.75초)마다 원이 하나씩 순차 등장
↓
각 원의 링이 3초에 걸쳐 목표 원 크기까지 축소
↓
링이 목표 크기에 겹치는 순간 = 완벽 타이밍
↓
클릭 시점 오차에 따라 PERFECT / GOOD / MISS 판정
↓
등급별 색상·문구 피드백 → 종합 결과 요약
```

## 1. 판정 3단계 확장

Day48의 판정은 "진행률 0.7 이상이면 Hit, 아니면 Miss"라는 이진 구조였다. 얼마나 정확했는지 구분할 수 없고, 완벽 타이밍 이후에 누르면 무조건 Miss가 되는 문제도 있었다.

이번에는 **완벽 타이밍(진행률 1.0)으로부터의 오차**를 기준으로 재설계했다.

```csharp
float offset = Mathf.Abs(shrinkProgressAtClick - 1f);
if (offset <= PerfectWindow) return Perfect;   // ±0.05 (≈ ±0.15초)
if (offset <= GoodWindow)    return Good;      // ±0.15 (≈ ±0.45초)
return Miss;
```

이렇게 바뀌면서 **조금 늦게 눌러도 판정을 받을 수 있는 늦은 판정 구간(Late Window)** 이 자연스럽게 생겼다. `RhythmCircleJudge`가 등급별 표시 문구와 색상까지 함께 관리하도록 정리해, View 쪽에 판정 관련 상수가 흩어지지 않게 했다.

판정 결과 집계용으로 `RhythmChallengeResult` 구조체를 새로 만들었다. Perfect/Good/Miss 개수와 함께 Perfect 1점·Good 0.5점 기준 정확도를 제공하는데, 이는 Day51에서 판정 등급을 전투 효과에 연동할 때 그대로 쓸 수 있는 형태다.

## 2. 원형 UI (사각형 → 진짜 원)

기존에는 스프라이트가 없는 `Image`를 그대로 써서 모든 원이 사각형으로 보였다. 프로젝트 아트 폴더(`UI/Art/Prototype`)를 확인해도 원형 애셋이 없었기 때문에, **런타임에 원형 스프라이트를 절차적으로 생성**하는 `RhythmCircleSpriteFactory`를 만들었다.

- 256×256 텍스처에 중심으로부터의 거리를 계산해 원을 그리고, 경계 1px에 알파 그라데이션을 넣어 안티에일리어싱 처리
- 채움 원(목표 원)과 속이 빈 링(축소하는 원) 두 종류를 생성하고 정적 캐싱 (도메인 리로드 대비 null 체크 포함)
- 흰색으로 생성해 색상은 `Image.color`에서 지정하도록 분리

또한 이 텍스처가 읽기 가능하다는 점을 활용해 `alphaHitTestMinimumThreshold`를 적용했다. 덕분에 **원 모양 그대로 클릭 판정**이 되어, 사각형 모서리의 빈 공간을 눌러도 반응하지 않는다.

## 3. 박자(BPM) 설계

Day48에서는 모든 원이 동시에 등장하고 각자 랜덤한 속도로 줄어들어서 "리듬"이라고 부르기 어려운 구조였다. 이번에 실제 박자 개념을 넣었다.

| 항목 | 값 | 설명 |
| --- | --- | --- |
| BPM | 80 | 한 박자 = 0.75초 |
| 등장 간격 | 1박자 | 원이 0.75초 간격으로 하나씩 등장 |
| 축소 시간 | 3초 (전 원 공통) | 모든 원이 같은 속도로 줄어듦 |

축소 시간을 랜덤이 아닌 **고정값으로 통일**한 것이 핵심이다. 등장 간격이 일정하고 축소 시간도 같으면, **판정 순간도 정확히 한 박자 간격**으로 떨어진다. 즉 플레이어는 일정한 리듬으로 클릭하게 된다. (Day48에서 요청받은 "3배 느리게"는 3초 고정값으로 그대로 유지)

## 4. 리듬게임 스타일 연출

`UltimateRhythmChallengeView`를 전면 재작성했다.

- 링이 2.8배 크기에서 목표 원 크기까지 축소되는 오스penu! 방식 접근 연출
- 원 안에 **순서 번호(1·2·3·4)** 표시, 등장 시 0.18초 페이드인
- **Perfect 구간에 진입하면 링이 금색, Good 구간은 초록색**으로 미리 바뀌어 타이밍을 시각적으로 알려줌
- 클릭 시 원 위쪽에 **PERFECT / GOOD / MISS 문구**가 등급 색상으로 팝업
- 화면 하단에 **BPM 표시와 박자마다 뛰는 비트 점** 추가
- 종료 시 `PERFECT n · GOOD n · MISS n` 요약 표시 (Miss가 0이면 금색 강조)
- 모든 텍스트에 어두운 외곽선을 넣어 밝은 전장 배경에서도 가독성 확보

## 5. 경계값 부동소수점 버그 수정

테스트 실행 결과 `Evaluate_WithinPerfectWindow_ReturnsPerfect`가 실패했다. `1f - 0.05f`는 float로 `0.949999988`이 되고, 이를 다시 `abs(0.949999988 - 1f)`로 계산하면 `0.050000012`가 되어 `PerfectWindow`(0.05)를 아주 미세하게 초과하면서 Good으로 밀려나는 문제였다.

판정 구간 경계에 정확히 걸린 입력이 한 단계 낮은 등급으로 떨어지는 것은 실제 플레이에서도 발생할 수 있는 문제이므로, 테스트를 완화하는 대신 **판정 로직에 경계 허용 오차(`BoundaryEpsilon = 0.0001f`)를 추가**해 해결했다. Miss 경계는 여전히 정상적으로 분리된다.
