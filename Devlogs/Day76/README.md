# Part 1. 표정 연결표 — `ExpressionCatalog`

## 어긋나 있던 것

75일차에 GPT로 넘긴 인수인계 문서에는 표정 파일 이름을 `smile` · `serious` 같은 **영어 7종**으로 적었다. 그런데 코드를 열어 보니 사정이 달랐다.

| 확인한 것 | 내용 |
| --- | --- |
| 대사 파일 | 캐릭터 대사 **892줄 전부**에 이미 `expression`이 적혀 있었다 |
| 표정 이름 | `미소` · `진지` · `부끄러움` 같은 **한글 12종** |
| 그림 찾는 방식 | 대사에 적힌 이름을 그대로 붙여 `CH_SERENA_미소.png`를 찾음 |

→ 이대로면 GPT가 만든 `CH_SERENA_smile.png`는 **넣어도 표정이 바뀌지 않는다.**

파일 이름을 바꾸는 대신, 게임 안에서 둘을 잇는 표를 만들었다. 대사 229편은 한 글자도 고치지 않았다.

## 연결표

| 그림 표정 | 대사에 적힌 이름 | 쓰는 줄 수 |
| --- | --- | --- |
| `normal` | 기본 | 203 |
| `smile` | 미소 · 흥미 | 194 |
| `serious` | 진지 · 각오 · 생각 · 경계 | 293 |
| `shy` | 부끄러움 | 82 |
| `surprised` | 놀람 · 당황 | 109 |
| `sad` | 슬픔 · 상처 | 11 |
| `angry` | 화남 · 분노 | **0** |

- 모르는 이름과 빈 값은 `normal`로 간다
- `angry`는 지금 대사에서 쓰는 곳이 없다. 앞으로 쓸 자리로 남겨 두었다

# Part 2. 스탠딩 찾는 순서와 표정 전환

## 찾는 순서

| 순위 | 찾는 파일 | 뜻 |
| --- | --- | --- |
| 1 | `{ID}_{표정 키}` | 그 표정 그림 |
| 2 | `{ID}_{대사에 적힌 이름}` | 예전 규칙으로 넣은 그림 |
| 3 | `{ID}_normal` | 그 표정이 아직 없을 때 기본 표정 |
| 4 | `{ID}` | 표정 이름이 없는 그림 |
| 5 | 색 실루엣 | 그림이 하나도 없을 때 |

처음에는 3번이 없었다. 그러면 표정 그림이 일부만 왔을 때 **없는 표정마다 예전에 코드로 그린 그림이 튀어나온다.** 그래서 기본 표정을 먼저 찾도록 한 단계를 넣었다.

## 표정 전환

- 지금까지는 표정이 **즉시** 바뀌었다
- 그림이 실제로 바뀔 때만, 이전 그림을 위에 겹쳐 두고 **0.1초 동안 투명하게** 만든다
- 말하는 사람만 바뀌고 표정이 그대로면 겹침이 일어나지 않는다
- CG가 화면을 덮는 동안에는 건너뛴다

# Part 3. 배경 마무리

## 비율 맞춤 — `BackgroundFit`

배경을 화면에 맞춰 **늘리고** 있었다. 코드로 그린 그라데이션일 때는 티가 나지 않았지만, 일러스트는 16:9가 아닌 창에서 찌그러져 보인다.

→ 비율을 지킨 채 화면을 다 덮을 때까지 키우고, 남는 쪽은 화면 밖으로 잘리게 했다.

| 화면 | 적용 |
| --- | --- |
| 대화 화면 (배경 · CG) | 적용 |
| 마을 (지도 · 구역) | 적용 |
| 상점 · 대장간 | **적용하지 않음** — 배경이 메뉴의 부모라서, 배경이 커지면 메뉴 위치가 함께 밀린다 |

## 배경 대체

상점 · 대장간 · 마을 지도 화면은 대사가 아니라 **화면이 직접** 배경을 부른다. 75일차에 받은 26장에는 이 세 곳의 그림이 없었다.

| 화면 | 전용 그림이 없을 때 |
| --- | --- |
| 상점 `SHOP` | 시장 `VILLAGE_MARKET` |
| 마을 지도 `VILLAGE` | 광장 `VILLAGE_PLAZA` |
| 대장간 `BLACKSMITH` | 코드로 그린 임시 그림 |

전용 그림을 넣으면 그쪽이 우선이다. 오늘 세 장 모두 받아서 지금은 전용 그림이 나온다. 규칙은 그림이 빠졌을 때를 위해 남겨 두었다.

# Part 4. GPT 그림 2차분 적용

## 받은 그림

| 구분 | 수 | 규격 |
| --- | --- | --- |
| 배경 | 4장 | 1672×941 |
| 스탠딩 | 84장 (12인 × 7표정) | 1024×1536 · 투명 PNG |

## 넣기 전에 검사한 것

그림 84장을 직접 읽어 픽셀 단위로 확인했다.

| 항목 | 결과 |
| --- | --- |
| 크기 | 84장 모두 같다 |
| 키 맞춤 | 12명 모두 머리 꼭대기(위에서 24px)와 발끝(1511px)이 같다 |
| 표정끼리 위치 | 얼굴 부분 약 **120×117px**만 다르고, 몸과 윤곽(투명도)은 **한 픽셀도 다르지 않다** |
| 투명도 | 몸 전체가 알파 253(99% 불투명). 눈에 띄지 않는다 |
| 투명 부분의 색 | 모두 검정. `.meta`의 `alphaIsTransparency: 1`이 가장자리 검은 테두리를 막는다 |

표정끼리 몸이 완전히 같으므로, 0.1초 겹침 전환에서 **두 겹으로 보이지 않는다.**

## 적용 방법

- `INN_NIGHT`는 PNG만 덮어쓰고 `.meta`(GUID)는 그대로 두었다
- 새 파일 87개는 같은 폴더의 기존 `.meta`를 본떠 GUID만 새로 만들었다. `.meta`를 PNG보다 **먼저** 써서, Unity가 기본 설정으로 먼저 가져가는 일을 막았다
- GPT의 작업 폴더(`_work`)는 넣지 않았다

## 알아둘 점

- **대사에 새 표정 이름을 쓰려면 `ExpressionCatalog`에 먼저 등록할 것.** 등록하지 않으면 기본 표정으로 나오고 테스트가 실패한다
- 표정 그림 파일 이름은 **영어 7종**이다. 대사에는 한글 이름을 적는다
- `BackgroundFit.Apply`는 **자식이 없는 전체 화면 배경에만** 쓸 것. 배경이 부모보다 커지므로 자식이 있으면 함께 밀린다
- 스탠딩 84장이 **113MB**다. 표정 72장은 얼굴 부분만 다르므로, 용량이 문제가 되면 얼굴 조각만 저장하는 방식으로 줄일 수 있다 (약 95MB)
- 예전에 코드로 그린 스탠딩 12장(`CH_SERENA.png` 등)은 이제 쓰이지 않지만 그대로 남아 있다
- 나타샤의 `sad` · `angry`는 눈썹 옆에 작은 점이 보인다
