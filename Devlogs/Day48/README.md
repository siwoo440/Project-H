# 프로젝트 H : 48일차 개발 로그

## 오늘 목표

48일차의 목표는 Phase 2의 첫 시스템인 **궁극기 리듬 챌린지**를 구축하는 것이었다. 원래 이 자리는 "Phase 1 전체 게임 루프 통합 QA" 예정일이었으나 "테스트하는 일차라면 그냥 넘어가자"는 판단에 따라 QA를 생략하고, 그 번호에 Phase 2의 첫 실제 구현 내용을 채워 넣었다. 로드맵상 원래 "리듬 Beat Clock·노트 생성 및 기본 Hit/Miss 판정"으로 잡혀 있었는데, 실제 협의 과정에서 배경음악 전체를 관리하는 박자 시계가 아니라 **궁극기를 사용할 때 발동하는 짧은 미니게임**(오스penu! 스타일로 줄어드는 원을 클릭하는 방식)으로 방향이 확정되었다.

핵심 흐름은 다음과 같다.

```text
궁극기 게이지 100% 도달
↓
캐릭터 초상화 클릭
↓
화면에 원 3~4개가 랜덤 위치에 등장 (서로 겹치지 않음)
↓
각 원이 일정 시간에 걸쳐 점점 작아짐
↓
플레이어가 적절한 타이밍에 클릭
↓
Hit / Miss 판정 → 결과 요약 표시 (전투 효과 연동은 후속 Day)
```

## 1. 리듬 챌린지 데이터 구조

`Assets/ProjectH/Scripts/Battle/Rhythm/` 폴더를 신설했다.

- `RhythmCircleData` — 원 1개의 위치(정규화 좌표)와 줄어드는 시간을 담는 순수 데이터
- `UltimateRhythmChallengeGenerator` — 3~4개 사이 랜덤 개수, 안전 영역(기존 HUD·패널과 겹치지 않는 범위) 내 랜덤 위치, 랜덤 줄어드는 시간을 생성하는 순수 static 클래스. `System.Random`을 주입받을 수 있어 EditMode 테스트에서 결정적으로 검증 가능
- `RhythmCircleJudge` — 클릭 시점의 줄어드는 진행률(0~1)을 기준으로 Hit/Miss를 가르는 판정 로직 (진행률 70% 이상이면 Hit). Perfect/Good 세분화는 후속 Day 몫으로 남겨둠

## 2. 화면 표시 및 입력 판정

`UltimateRhythmChallengeView`가 실제 화면에 원을 그리고 입력을 받는다.

- 궁극기 발동 시 `Show()`가 호출되어 Runtime Canvas를 생성하고 생성된 원 데이터만큼 클릭 가능한 원 오브젝트를 배치
- 매 프레임 각 원의 배율을 시작 배율(2.6배)에서 1배(목표 크기)로 선형 보간하며 축소
- 클릭 시 그 시점의 진행률로 `RhythmCircleJudge`를 호출해 Hit(초록)/Miss(빨강) 색상으로 즉시 피드백
- 시간 초과 시 자동 Miss 처리
- 모든 원의 판정이 끝나면 "HIT n/총n" 요약 문구를 잠깐 표시하고 자동 정리

## 3. 궁극기 발동 트리거 연결 및 버그 수정

기존에는 궁극기를 쓸 방법이 사실상 없었다 — HUD 카드의 작은 "ULT READY" 텍스트 버튼만 있었고, 이것도 사용자가 실제로 찾아 누르기 어려운 구조였다. 요청에 따라 **캐릭터 초상화 자체를 버튼으로 만들어**, 게이지가 100%가 되면 초상화가 밝은 금색 톤으로 바뀌고 클릭으로 궁극기가 발동되도록 `BattleHudCardView`를 수정했다.

1차 적용 후에도 클릭이 먹지 않는 문제가 있었는데, 원인은 `Battle.unity`에 저장된 초상화 Image의 `raycastTarget`이 애초에 장식용으로 꺼져 있었던 것이었다(`m_RaycastTarget: 0`). Button을 추가해도 `raycastTarget`이 꺼진 Graphic은 레이캐스트에 아예 걸리지 않기 때문에 클릭이 통과해버리고 있었다. `portraitImage.raycastTarget = true`를 명시적으로 켜서 해결했다.

## 4. 실제 플레이 확인 후 세부 조정

실제로 사용해 본 뒤 두 가지 조정 요청이 있었다.

- **원들이 서로 겹침**: `UltimateRhythmChallengeGenerator`에 겹침 방지 로직을 추가했다. 새 원을 배치할 때마다 이미 배치된 원들과의 중심 거리(기준 해상도 1920×1080 기준 픽셀 환산)를 계산해, 원 크기 기준 최소 거리(1.15배 여유)를 만족할 때까지 최대 40회 재시도한다.
- **줄어드는 속도가 너무 빠름**: 줄어드는 시간을 0.9~1.4초에서 **2.7~4.2초(3배)** 로 늘렸다.

이 과정에서 `View`가 자체적으로 갖고 있던 원 크기 상수를 `Generator`의 공용 상수로 통합해, 두 값이 서로 어긋나 겹침 계산이 부정확해지는 일이 없도록 정리했다.

## 5. EditMode 테스트

`UltimateRhythmChallengeTests`를 신규 작성했다.

- 생성 원 개수가 항상 3~4개 범위인지
- 생성 위치가 안전 영역을 벗어나지 않는지
- 생성된 원들이 서로 겹치지 않는지 (50회 반복 검증)
- 생성 줄어드는 시간이 설정된 범위 안인지
- Hit/Miss 판정 경계값이 정확한지
- 범위를 벗어난 진행률 입력이 안전하게 보정되는지

## 7. 범위 제한 준수

이번 Day48은 **원 생성·화면 표시·기본 Hit/Miss 판정·발동 트리거**까지만 구현했다. Hit/Miss 결과는 현재 로그로만 남기고 있으며, 다음 항목은 아직 연결하지 않았다.

- Perfect/Good/Miss 세분화 (압축 로드맵 Day49)

- 판정 결과가 실제 궁극기 피해·회복에 영향을 주는 연동 (Day51)
