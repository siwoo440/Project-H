사용자와 정한 방식

1. 네메시스의 정체는 **(a) 봉인된 고대 존재**
2. 최종장에 새 동료 합류는 없음 — 12인이 **한 마디씩** 하는 구성
3. 최종 보스는 DG016보다 한 단계 위 + **3페이즈**
4. 엔딩 선택은 **플래그 2개**(봉인 장치 / 이름) → 72일차에 조합

## 밸런스 검증

67일차 시뮬레이터로 **17던전 전체**를 다시 돌려 실패 0건. DG017은 게임에서 가장 빡빡하다.

| 웨이브 | 처치 | 여유 비율 | 기준 |
| --- | --- | --- | --- |
| 일반 1 | 45.1초 | 2.11 | ≤60초 · ≥2.0 |
| 일반 2 | 47.0초 | 2.16 | 〃 |
| 일반 3 | 51.8초 | 2.05 | 〃 |
| 보스 | 130.3초 | 1.23 | 60~150초 · ≥1.2 |

참고로 DG016의 일반 웨이브 여유는 2.87~6.35다.

### 튜닝 과정에서 겪은 일

처음 웨이브 구성은 `[잔향×2 + 침식병]`, `[파수꾼 + 잔향 + 망령]`, `[파수꾼×2 + 잔향×2]`였는데, **어떤 수치를 넣어도 조건을 만족할 수 없었다**.

- 웨이브 0은 체력이 큰 기존 몬스터(침식병 16,600)가 섞여 있어 처치 시간을 맞추려면 잔향 체력이 **22,000 이상**이어야 했고
- 웨이브 2는 잔향 2마리가 또 들어가 총 체력이 넘쳐 **파수꾼 체력이 7,000 이하**여야 했다

같은 몬스터에 서로 모순되는 요구가 걸린 구조였다. 웨이브를 `[잔향×3]`, `[파수꾼 + 잔향 + 침식병]`, `[파수꾼×2 + 잔향]`으로 바꿔 각 몬스터가 한 웨이브에 몰리지 않게 하자 바로 풀렸다.

**탐색 스크립트의 버그도 하나 있었다.** 평가 함수가 `(처치 시간, 생존 시간)`을 돌려주는데 두 번째 값을 *여유 비율*로 알고 비교하고 있었다. `ratio ≤ 2.6` 같은 조건이 영영 참이 되지 않아 "조합 없음"만 나왔다. `survive / clear`를 반환하도록 고친 뒤에야 정상 동작했다.

## 알아둘 점

- 대사 선택지에 `"flag": "..."`를 넣으면 그 선택지를 고를 때 스토리 플래그가 남는다. 메인 스토리에서는 `ChapterService`가 자동으로 기록하고, 다른 화면에서는 `ChapterService.ApplyChoiceFlags(save, runner)`를 직접 부르면 된다
- 마왕성 지역만 던전이 3개다. 지역당 2던전을 검사하는 테스트는 이 예외를 명시적으로 허용한다
- 던전을 추가할 때 `rewardExp`는 반드시 `60 + 20 × 권장레벨`이어야 한다 (`DungeonLadderTests`가 공식으로 검사)
- 밸런스를 맞출 때 같은 몬스터가 여러 웨이브에 몰려 있으면 요구 조건이 서로 모순될 수 있다. 수치를 바꾸기 전에 **웨이브 구성**을 먼저 의심할 것
- `System.Random`을 쓰는 파일에서 `Random.Range`를 부르면 이름이 모호해진다. `UnityEngine.Random.Range`로 명시할 것
