# 프로젝트 H : 55일차 개발 로그

## 오늘 목표

55일차의 목표는 **노드형 던전 탐험 및 랜덤 이벤트·보상·함정 노드**다.

지금까지 던전은 **"문 열면 바로 보스방"** 이었다. 입장 버튼을 누르면 곧장 전투가 시작되고, 이기면 끝이었다. 탐험하는 느낌이 전혀 없었다.

Day55는 던전을 **지도가 있는 탐험**으로 바꾼다. 입장하면 전투 대신 **왼쪽에서 오른쪽으로 이어지는 갈림길 지도**가 먼저 뜨고, 연결된 노드 중 하나를 골라 한 칸씩 나아가 마지막 보스에 도달한다.

```text
[입구]                                                   [보스]
 전투 ─┬─ 이벤트 ─── 휴식 ─┐
       └─ 보물  ─┬── 전투 ─┼─── 정예 ─── ···  ───  보스
 전투 ────────── 함정 ───┘
```

추가 작업으로 두 가지를 더 진행했다.

- **로딩창** — 우하단 달리는 실루엣과 로딩바, 중앙 하단 Tip. 전투에 들어갈 때는 **4명이 터널을 빠져나오는 연출**
- **테스트 간 상태 누수 버그 수정** — Test Runner에서 발견된 5건

## 1. 지도 모델과 생성기 (신규)

`DungeonMap` / `DungeonMapNode` — 노드마다 **층(왼쪽→오른쪽)**, **층 내 위치(위→아래)**, 종류, 다음 층 연결 목록을 가진다.

노드 종류는 7가지다.

| 노드 | 내용 |
| --- | --- |
| 전투 | 던전 일반 웨이브 1개 |
| 정예 | 일반 웨이브 2개 연속 |
| 이벤트 | 선택지 2개, 확률 결과 |
| 보물 | 즉시 골드 획득 |
| 함정 | 다음 전투에 불리한 효과 |
| 휴식 | 다음 전투에 유리한 효과 |
| 보스 | 던전 전체 웨이브 (마지막 층) |

`DungeonMapGenerator.Generate(시드, 층수)`는 순수 static 클래스다. **같은 시드면 같은 지도**가 나오므로 테스트가 쉽다. 실제 입장 시에는 시간 기반 시드를 넣어 매번 다른 지도가 나온다.

**생성 규칙**

- 층수는 **보스 층을 포함**한다
- 첫 층은 전투 2개, 마지막 층은 보스 1개, 중간 층은 2~3개
- 중간 층 비중: 전투 45 · 이벤트 18 · 보물 12 · 함정 10 · 휴식 10 · 정예 5
- 함정·휴식은 **연속 층에 나오지 않는다**

**연결 규칙**이 가장 신경 쓴 부분이다.

1. 각 노드는 **세로 위치가 가장 가까운** 다음 층 노드와 기본 연결 → 모든 노드에 출구 보장
2. 50% 확률로 **출발 위치 쪽 인접 노드**와 추가 연결 → 선택지가 생기되 선이 잘 교차하지 않음
3. 진입 연결이 하나도 없는 다음 층 노드는 가장 가까운 노드에서 강제 연결 → **고립 노드 없음**

결과적으로 **어느 길로 가도 반드시 보스에 도달**한다. 이 성질을 50개 시드 × 모든 노드에서 너비 우선 탐색으로 검증했다.

## 2. 던전별 층수

처음에는 요청대로 DG001~DG004를 **1·2·3·4층**으로 설정했다. 이 경우 DG001은 보스 노드 하나뿐이라 입장하자마자 보스전이 됐다.

이후 **던전마다 노드를 4~5개씩 추가**해 달라는 요청을 받았다. 1층 던전은 층을 늘리지 않으면 노드를 넣을 자리가 없어서, 각 던전에 **2층씩 더해 3·4·5·6층**으로 조정했다. 중간 층 하나가 노드 2~3개이므로 층 2개가 늘면 평균 4.5~5개가 추가되고, 던전 순서대로 길어지는 구조도 유지된다.

| 던전 | 층수 | 평균 노드 |
| --- | --- | --- |
| DG001 무너진 성역의 숲 | 3 | 약 5.5개 |
| DG002 성역 외곽 폐허 | 4 | 약 8개 |
| DG003 침식된 회랑 | 5 | 약 10.5개 |
| DG004 심연의 관문 | 6 | 약 13개 |

`DungeonData.mapFloorCount`로 인스펙터에서 바로 조정할 수 있다.

## 3. 이벤트·함정·휴식 (신규)

`DungeonEventCatalog`에 이벤트 4종을 코드 데이터로 정의했다. 각각 선택지 2개와 확률 결과를 가진다.

| 이벤트 | 선택지 A | 선택지 B |
| --- | --- | --- |
| 수상한 제단 | 기도한다 (60% 공격력 +25% / 40% 명중 -25%) | 지나친다 |
| 떠돌이 상인 | 부적을 산다 (골드 소모 → 방어 +30%) | 거절한다 |
| 무너진 야영지 | 짐을 뒤진다 (70% 골드 / 30% 공격 속도 -30%) | 쉬어간다 (받는 피해 -15%) |
| 침식된 샘 | 마신다 (50% 공격 속도 +25% / 50% 마법 저항 -25%) | 떠난다 |

함정 3종(둔화 · 실명 · 저항 감소)과 휴식 3종(공격 · 방어 · 피해 감소)도 준비했다.

모든 효과가 **Day51 Modifier**라서 다음 전투에서 아군 초상화 위에 상태이상 칩으로 그대로 표시된다. 새 효과 시스템을 만들지 않았다.

## 4. 탐험 진행 상태 (신규)

`DungeonRunState` — 씬을 오가도 유지되는 static 상태. 현재 위치, 완료 노드, 다음 전투 효과, 획득 골드를 기억한다.

한 가지 함정을 미리 막았다. 전투 노드에 들어갔다가 **메뉴로 도망쳐 돌아오면**, 현재 위치는 이미 그 노드로 이동해 있어서 다음 층으로 건너뛸 수 있게 된다. 그래서 결과가 없는 전투 노드가 있으면 **그 노드만 다시 선택 가능**하게 했다.

```csharp
if (PendingBattleNodeId >= 0)
{
    result.Add(Map.GetNode(PendingBattleNodeId));   // 재도전만 허용 (건너뛰기 방지)
    return result;
}
```

## 5. 전투 연결

| 연결 지점 | 변경 |
| --- | --- |
| `DungeonBattleFormationRuntimePatch` | 노드 종류별 웨이브 — 일반 1개 · 정예 2개 · 보스 전체 |
| `BattleResultData` | 보상 배율 일반 40% · 정예 70% · 보스 100%, 일반 전투는 드롭 없음 |
| `BattleResultCommitService` | 던전 클리어·별점은 **보스 노드에서만** 기록 |
| `BattleScreenController` | 전투 종료 시 탐험 상태에 승패 보고 |
| `BattleSkillRuntimeDriver` | 함정·휴식 효과를 전투 시작 시 아군에게 적용 |

일반·정예 노드는 **마지막 웨이브를 제외**하고 고른다. DG004의 마지막 웨이브는 Day54 보스(침식의 파수꾼)라서, 보스 노드에서만 만나야 하기 때문이다.

함정·휴식 효과를 전투 시작 시점에 거는 부분에서 **Day52·53에서 겪은 초기화 순서 함정**을 다시 피했다. 스킬 상태 초기화(`ResetAll`)는 `BattleSkillExecutor.Configure`에서 일어나고, 같은 시점에 `BattleSkillRuntimeDriver`가 추가된다. 그래서 Driver의 `Update`에서 **아군이 생성된 것을 확인한 첫 프레임에 한 번만** 적용하면 초기화에 지워지지 않는다.

탐험 중이 아닌 전투는 배율 1.0 · 클리어 기록 · 드롭 모두 **기존과 완전히 같다.**

## 6. 가로형 지도 UI (신규)

`DungeonMapOverlayView` — 던전 선택 화면 위에 런타임으로 생성되는 오버레이. 씬 파일은 건드리지 않았다.

- 왼쪽 입구 → 오른쪽 보스로 층이 가로 배치, 우상단에 `입구 → → → 보스`
- 노드는 Day49 원형 스프라이트를 재사용한 원, 종류별 색상, 보스는 1.3배 크기
- **선택 가능 노드는 맥동**, 이동 가능한 연결선은 금색, 지나온 길은 밝게, 완료 노드는 어둡게
- 하단에 탐험 골드와 **다음 전투 효과** (불리 빨강 / 유리 하늘색)
- 이벤트는 선택지 팝업, 보물·함정·휴식은 결과 팝업, `탐험 포기` 확인 팝업

연결선은 두 노드 좌표 사이에 얇은 이미지를 **길이·각도 계산으로 회전**시켜 그렸다. 좌표 계산 전에 `Canvas.ForceUpdateCanvases()`로 지도 영역의 실제 크기를 확정해야 선이 정확히 이어진다.

던전 선택 버튼 문구는 `전투 시작` → **`탐험 시작`** 으로 바꿨고, `DungeonMapRuntimePatch`가 전투에서 돌아오면 **지도를 자동으로 다시 연다.** 보스를 잡았거나 패배했으면 클리어/실패 요약이 뜬다.

## 7. 로딩창 (신규)

**구성** — 검은 배경 위에

- 우하단: 곱슬머리 아이 실루엣이 달리고 곰인형이 뒤따라온다. 그 아래 로딩바와 `NOW LOADING...` · 진행률
- 중앙 하단: `Tip :` + 무작위 팁 (14종, 연속 중복 없음)

아트 에셋이 없어서 **Day49 원형 스프라이트를 조합해 실루엣을 코드로 그렸다.** 팔다리는 관절(위쪽 끝) 기준 피벗으로 엇갈려 흔들리고, 몸은 한 주기에 두 번 튀어오르며, 떠오를수록 발밑 그림자가 줄어든다.

**구조** — `SceneLoader`에 `LoadStarted` 이벤트를 추가하고 로딩창이 이를 구독한다. Core 영역이 UI를 몰라도 되도록 분리했다. 로딩창은 `DontDestroyOnLoad`라 씬이 바뀌어도 살아 있다.

로컬에서는 씬이 0.1초 만에 로드돼 로딩창이 번쩍 사라지므로, `allowSceneActivation`을 잠시 막아 **최소 표시 시간**을 보장한다. 로딩바는 실제 진행률과 최소 시간 중 **느린 쪽**을 따라 차고, 다 차면 씬 활성화를 허용한다.

**빈도 조절** — 처음엔 모든 전환에 떠서 너무 자주 보였다. 사용자와 논의해 **무거운 전환에만** 띄우도록 바꾸고 최소 시간도 1.1초 → 0.7초로 줄였다.

| 전환 | 로딩창 |
| --- | --- |
| 타이틀 → 로비 | 우하단 모드 |
| 던전 선택 → 전투 | **터널 모드** |
| 전투 → 던전 선택 | 우하단 모드 |
| 로비 ↔ 메뉴 화면 | 없음 |

## 8. 전투 진입 터널 연출

전투에 들어갈 때는 **화면 중앙에서 4명이 달리다가 터널을 빠져나오듯** 전투 화면으로 이어지게 했다.

**로딩 중 (터널 안)**
- 4명(양갈래 · 포니테일 · 단발 · 긴 머리)이 키와 박자를 달리해 나란히 달린다
- 발밑 점선이 뒤로 흘러 속도감을 주고, **화면 오른쪽 끝의 출구 빛**이 진행률에 따라 밝아진다

**전투 씬 준비 완료 (출구)**
- 로딩바·Tip이 먼저 사라지고 러너들이 **전력질주**로 바뀐다
- 검은 막이 **오른쪽에서 왼쪽으로** 0.95초에 걸쳐 걷히고, 경계에서 빛이 번진다
- 경계가 러너를 지나가는 순간 해당 러너가 **빛 속으로 사라진다** — 맨 앞 사람부터 차례로 터널을 빠져나간다

구현을 위해 검은 배경을 **앵커로 폭을 줄일 수 있는 막**으로 바꾸고, 막 경계와 빛 번짐에 쓸 가로 그라데이션 텍스처를 코드로 생성했다. 러너 생성 코드는 머리 모양만 바꿔 재사용하는 함수로 정리해, 우하단 곱슬머리 러너까지 같은 함수로 만든다.

## 9. 버그 수정 — 테스트 간 상태 누수

Test Runner에서 5개 테스트가 실패했다. 모두 **피해가 정확히 1.5배**로 나왔다. Day52 속성 약점 배율이다.

| 테스트 | 피해량 |
| --- | --- |
| 방어 감소 | 105 → 158 |
| 주기 피해 | 30 → 45 |
| 이브 궁극기 | 220 → 330 |
| 릴리아 궁극기 | 160 → 240 |
| 릴리아 실행기 | 260 → 390 |

원인은 **속성 등록이 테스트 사이로 새어 나간 것**이었다.

1. `BattleStatsFactoryTests` 등이 실제 캐릭터 에셋으로 `"ALLY_0"`을 만들면 팩토리가 그 캐릭터 속성(예: 세레나 = 빛)을 등록한다
2. 이 등록은 **전투 종료 시에만** 지워지는데, 테스트에는 전투 종료가 없다
3. 뒤이은 테스트가 `new BattleStats("ALLY_0", ...)`로 속성 없는 스탯을 만들어도 **공격 속성 상속 규칙** 때문에 남은 빛을 물려받는다
4. 대상은 무속성이고 **무속성은 빛에 약점**이라 1.5배가 된다

**실행 순서에 따라 결과가 달라지는** 전형적인 테스트 격리 문제였다. 테스트에 초기화만 넣는 대신 근본을 고쳤다. 실제 게임에서도 웨이브·전투 사이에 RuntimeId가 재사용되면 같은 문제가 생길 수 있기 때문이다.

- 스탯 **생성자**가 같은 RuntimeId에 남아 있던 속성·흐트러짐 상태를 비운다
- 팩토리는 순서를 **"등록 → 생성"에서 "생성 → 등록"** 으로 바꿨다

이제 **"새 스탯 = 깨끗한 상태"** 가 보장된다. Day52·53에서 초기화를 전투 종료 시점으로 옮긴 결정의 빈틈이 여기서 드러났고, 이번에 메웠다. 재현 조건을 그대로 만든 회귀 테스트를 추가했다.
