# Part 1. 그림 인수인계 문서

그림을 다른 도구에서 만들면 **이름 · 크기 · 색이 조금만 어긋나도** 게임에 바로 들어가지 않는다. 그래서 코드가 그림을 읽는 방식에 맞춰 규칙을 정리해 넘겼다.

| 항목 | 내용 |
| --- | --- |
| 스타일 | 밝은 일본 애니메이션풍 판타지 · 글자와 워터마크 없음 · 성인 캐릭터 · 선정적인 노출 없음 |
| 캐릭터 색표 | 12인의 머리 · 머리 그림자 · 눈 · 옷 · 피부 색과 앞머리 모양 (73일차 초상화와 같은 값) |
| 스탠딩 | 512×1024 투명 PNG · 표정 7종은 **몸 위치를 똑같이** 유지 |
| 초상화 · 컷인 · 배경 | 512×512 / 1280×720 / 1280×720 |
| 파일 이름 | `CH_SERENA_smile.png`처럼 **대소문자까지 그대로** |
| 여관 "특별한 밤" | 그리지 않음. 게임에서 화면을 어둡게 하는 연출만 사용 |

같은 이름으로 덮어쓰면 코드를 고치지 않아도 바뀐다. 63일차부터 로더가 **정식 그림을 먼저 찾고, 없을 때만 임시 그림을 쓰기** 때문이다.

# Part 2. 대화 배경 26장 교체

## 받은 그림 점검

| 점검 | 결과 |
| --- | --- |
| 형식 | 26장 모두 정상 PNG (RGB) |
| 크기 | 모두 **1672×941** — 비율 1.777로 16:9와 거의 같아 화면에 맞게 표시됨 |
| 이름 | 기존 배경 키 27개 중 **26개와 일치** |
| 내용 | 여관(`VILLAGE_INN`) · 침식 공간(`NOIR`) · 바다 균열(`SEA_RIFT`)을 열어 이름과 그림이 맞는지 확인 |

## 적용 방법

- PNG만 덮어쓰고 **`.meta`는 그대로 두었다**
  - GUID가 유지되어 이 배경을 쓰는 화면의 참조가 끊기지 않는다
  - `maxTextureSize: 2048`이라 1672 크기가 줄지 않는다
  - `nPOTScale: 0`이 이미 들어 있어 2의 거듭제곱으로 늘거나 줄지 않는다
- 원본 폴더는 복사만 하고 건드리지 않았다
- 코드 변경 없음

## 교체한 배경

| 구분 | 배경 |
| --- | --- |
| 시간대 | `MORNING` · `DAY` · `EVENING` · `NIGHT` |
| 마을 | `VILLAGE_PLAZA` · `VILLAGE_MARKET` · `VILLAGE_ONSEN` · `VILLAGE_INN` · `VILLAGE_GUILD` |
| 실내 | `ALCHEMY_LAB` · `GUILD_HALL` · `CORRIDOR_MORNING` · `OBSERVATORY_NIGHT` · `SANCTUARY_PRACTICE` |
| 거리 · 시설 | `BACK_ALLEY` · `SOUTH_GATE` · `FORTRESS_YARD` · `GARDEN_POND` · `CATHEDRAL_DUSK` · `TEMPLE_EAST` |
| 지역 | `KARNIAN` · `SILVARAN` · `DESERT` · `RUINS_CAMP` · `SEA_RIFT` |
| 침식 | `NOIR` |

- 교체 파일 26개 · 새 파일 0개 · `.meta` 변경 0개

## 알아둘 점

- **`INN_NIGHT`(밤의 여관 객실)가 아직 없다.** 이 배경만 코드로 그린 그림이라 그림체가 다르다. `VILLAGE_INN`은 1층 홀이라 객실 장면에는 맞지 않는다
- 새 배경은 **실사에 가까운 판타지 느낌**이고 채도와 명암 대비가 높다. 앞으로 받을 스탠딩 · 초상화와 나란히 놓고 그림체를 맞춰 볼 것
- 그림 파일이 커서 앞으로 스탠딩 84장까지 들어오면 저장소가 크게 늘어난다. 필요하면 Git LFS를 검토할 것
